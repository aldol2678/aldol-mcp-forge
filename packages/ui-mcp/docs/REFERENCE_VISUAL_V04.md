## ui_reference_analyze

Input: `source` string, `source_format: html | ui-json` (default html), optional
`css` string. Static input only; no URLs, fetches, script evaluation, browser,
login, remote CSS or private API inspection. `ui-json` means existing ALDOL UI
JSON 0.1–0.3, not arbitrary vendor JSON. Generic JSON adaptation is not claimed.

```json
{"source":"<meta name=\"viewport\" content=\"width=device-width\"><main><article class=\"card\"><button>Save</button></article></main>","source_format":"html","css":"@media(max-width:390px){.card{padding:12px}}"}
```

Outputs: screens, components, layout_regions, repeated_components,
interaction_candidates, responsive_evidence, tokens, source_evidence, confidence,
unknowns, unmapped_features, ui_spec_draft and bonsae_spec_draft.
Each component has an evidence ID and either semantic or class-heuristic basis.
Evidence uses input element index/line or JSON path. Inline styles use synthetic
stylesheet indices, not original HTML line numbers. CSS media/container evidence
includes recognized width/height breakpoints; it does not evaluate cascade.
Repeated roles are candidates, not proof of identical React components.

Source text, script bodies, form values, raw selectors and URLs are not echoed.
Safe literal CSS colors/lengths are recorded as observations, not auto-approved
design tokens. CSS variables are not resolved or automatically mapped to brand
roles. No geometry, occlusion or overflow is inferred from declarations alone.

At most 200000 combined UTF-8 bytes, 3000 HTML elements, depth 64, 200 returned
components, 200 responsive records, 100 token observations. UI JSON also inherits
the existing core limits. Output caps and omitted draft components are disclosed.
Empty/unrecognized input returns INSUFFICIENT_EVIDENCE with null drafts. Invalid
JSON, unsupported format and excessive size/depth raise safe MCP tool errors.

## Integration contract

1. Analyze supplied source independently.
2. Review `bonsae_spec_draft`; this is compatible intermediate data, not a claim
   that online BONSAE authored or approved it.
3. Pass `json.dumps(result['bonsae_spec_draft'])` to `ui_import_bonsae`.
4. Pass returned `ui_spec_json` to `ui_validate`, `ui_generate`, `ui_audit` and
   `ui_review`. Existing importer creates up to 20 structural card placeholders.
5. Implement actual controls/layout in the host, then capture matching screenshots
   and invoke `ui_visual_compare` independently.

The direct `ui_spec_draft` is generated by that same importer and validated by
the existing core. No live game data, state, economy or host actions are imported.
No online BONSAE dependency, aesthetic acceptance or release authorization exists.

## ui_visual_compare

Inputs: `reference_image`, `candidate_image` are raw base64 PNG/JPEG bytes.
Do not pass URLs, filenames, data URLs, SVG or GIF. `comparison_mode` is layout,
pixel or region; `viewport` is mobile/tablet/desktop/unspecified; `tolerance` is
integer 0–64 (default 24); `same_state` is caller assertion, default false.

```python
import base64
from pathlib import Path
args = {
    'reference_image': base64.b64encode(Path('before.jpg').read_bytes()).decode(),
    'candidate_image': base64.b64encode(Path('after.jpg').read_bytes()).decode(),
    'comparison_mode': 'region', 'viewport': 'mobile', 'same_state': True,
}
# session.call_tool('ui_visual_compare', args)
```

Each image is limited to 180000 encoded-file bytes / 240000 base64 characters,
2000000 decoded pixels and 4096 pixels per side. Two maximum base64 inputs plus
RPC overhead fit the existing 512000-byte standalone HTTP limit. Vercel's existing
3000000-byte limit is unchanged. Use a smaller capture or reasonable JPEG quality
when a screenshot exceeds the byte limit; the engine never silently rescales.

PNG chunk boundaries are checked before decode; compressed ancillary metadata
and animated PNG are refused. Pillow validates and loads only PNG/JPEG with
pixel/dimension preflight. Alpha composites on white; EXIF orientation is not
applied. A process-local single-flight gate rejects simultaneous comparisons
as busy. Bounds constrain per-call work; this is not a global multi-instance
rate limiter or a hard process CPU timeout. Existing auth/body limits remain.

| Mode | Difference mask / regions |
|---|---|
| layout | Symmetric missing/added edge pixels, per-channel FIND_EDGES threshold 32, one-pixel matching tolerance |
| pixel | Maximum RGB-channel difference exceeds caller tolerance, full resolution |
| region | Union of pixel and edge masks, grouped into at most 16×16 coarse tiles |

All modes return both pixel difference and layout similarity. Similarity is
matched edge support / total edge support, on 0–1 scale; blank images have null
layout similarity. No empty-margin padding of similarity. Coarse changed regions
use four-connected tile components and original image coordinates, not CSS pixels.
Connected bounds can contain unchanged gaps. Missing panels are difference
candidates; this tool does not semantically identify an omitted form/button.
Contrast, shadows, text rasterization and low-contrast recoloring can alter edges.

Dimensions/aspect ratios are always returned. A mismatch returns INCOMPARABLE,
null metrics and no diff; no crop, resize or shared-height scoring. A matched
canvas returns COMPARED, never PASS. `same_state=true` is not independently
verified; fonts, DPR, capture timing, scroll position and UI state must be controlled.
Scores are not UX, accessibility, functional or release approval.

`diff_artifact` is an inline base64, binary PNG difference mask; no files are
written, no screenshots logged, no persistence or telemetry added. A mask can
still reveal sensitive geometry or text shapes: clients should treat it as private,
avoid logging base64, and offer explicit local download/retention controls.

## Mobile and subsequent work

Official documentation checked 2026-10-23:
- https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt
  says custom MCP connection setup is web only.
- https://developers.openai.com/api/docs/guides/custom-mcp-server says use ChatGPT
  web to add a custom server.
- https://learn.chatgpt.com/docs/plugins says available plugins can be used in
  mobile Chat/Work. Do not extend the web-only setup statement into a blanket
  assertion that every installed MCP plugin cannot run on Android.

Direct mobile custom-server setup: UNSUPPORTED per the cited connection docs.
This candidate's installed-plugin Android invocation: NOT VERIFIED (no physical
device or refreshed test plugin); do not mark PASS or claim universal prohibition.
ChatGPT host candidate invocation is also not verified by SDK transport tests.

Mobile web/PWA boundary (design only): responsive file-picker/text inputs → client
size checks and state/viewport confirmation → authenticated same-origin backend
session → the same Python engines/MCP adapter. Keep the service Bearer key only
on the backend; short-lived secure HttpOnly session + CSRF/Origin checks, no token
in URL/localStorage, no image caches/service-worker retention, no wildcard CORS.
Return compact regions first and optional diff download. Do not weaken existing
MCP Origin policy; add a separately reviewed same-origin client/BFF later.
No full PWA, auth change, database or service payment is in this PR.

Deferred dependencies: flow audit needs explicit state graphs and trusted runtime
evidence; advanced tokens need computed styles/cascade; accessibility needs DOM
semantics plus keyboard/focus checks; MAJUNG requires a versioned review-evidence
contract; SEUM/Game Ops need provenance-bearing browser reports; Asset Factory
needs rights/provenance-bearing asset IDs. None is implemented or auto-activated.
